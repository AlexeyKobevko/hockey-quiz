# Перенос и обновление Hockey Quiz

Эта инструкция описывает отдельную операционную задачу. `npm run build` и тесты не выполняют деплой, не меняют Caddy/systemd/firewall и не обращаются к действующему сайту.

## Комплект релиза

На машине сборки используйте закреплённую Node (`.node-version`), `npm ci`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`. Браузеры для e2e подготовьте по README. Весь каталог `dist/` — самостоятельный release: server/, shared/, client/ и package.json. Его содержимое можно скопировать в новый каталог и запустить `npm start` внутри него без исходников, node_modules и инструментов разработки. Из корня репозитория `npm start` запускает dist/server/main.js.

Нельзя копировать только серверный JS или отдельный CSS. Сборка клиента и сервера, вопросы, общие модули и статические файлы составляют один релиз. В клиентской части нет полного ключа вопросов. Не раздавайте корень репозитория, server/ или shared/ через Caddy.

## Параметры нового VPS

Перед установкой проверьте существующие процессы, сайты, порты, пользователя и права. Не меняйте глобальную Node других приложений. Подготовьте отдельный runtime Node 24 вне /home и непривилегированного пользователя проекта.

Выберите и зафиксируйте:

- APP_USER и APP_GROUP — отдельная учётная запись службы.
- APP_DIR — каталог приложения, содержащий releases/ и current -> releases/<release>.
- NODE_BIN — абсолютный путь совместимого runtime, доступного службе при ProtectHome=true.
- QUIZ_PORT — свободный внутренний порт; 3707 только пример/default, занятый порт не захватывать.
- SITE_DOMAIN — принадлежащее оператору имя или проверенное бесплатное имя wildcard-IP DNS для нового публичного IP. Покупка домена не требуется.

В `hockey-quiz.service.in` замените все @...@, проверьте unit через systemd-analyze verify и только затем установите как отдельную службу. Runtime и весь current/release должны читаться APP_USER; секретов приложению не нужно. Служба слушает только 127.0.0.1. Для автозапуска используется WantedBy=multi-user.target, для рестарта — Restart=on-failure. NODE_BIN не должен указывать в домашний каталог, закрытый ProtectHome.

Caddy-сниппет использует SITE_DOMAIN и QUIZ_PORT из окружения процесса Caddy. Эти значения нужно передать его менеджеру службы; переменная только в интерактивном shell не меняет окружение уже работающего Caddy. Также допустимо подставить проверенные значения в отдельную копию сниппета вместо env-плейсхолдеров.

## Первый запуск или перенос

1. Проверить DNS нового имени, доступность 80/443 и свободный loopback-порт, сохранить фактические конфиги затрагиваемых служб с датой. Не менять SSH и чужие reverse proxy.
2. Разместить полный релиз в APP_DIR/releases/<release>, создать current и проверить чтение файлов пользователем службы. Сначала проверить его на отдельном локальном порту и штатно завершить тестовый экземпляр.
3. Подготовить и проверить отдельный unit. Не заменять units других приложений. Включить автозапуск и запустить только проектную службу в рамках отдельного согласованного деплоя.
4. Добавить изолированный site/import в реально используемый Caddyfile. Не заменять целиком действующий конфиг. До reload выполнить `caddy validate --config <actual-config>` с настроенными параметрами.
5. Получить публично доверенный сертификат автоматически через Caddy. Не использовать tls internal или curl -k. SSE передаётся с flush_interval -1 и heartbeat; WebSocket для игровых событий не нужен.
6. Проверить local /api/health, HTTP -> HTTPS, сертификат, главную страницу, CSS/JS/графику и реальную доставку SSE. Пройти создание комнаты, вход двух игроков, независимые ответы, раскрытие и reconnect. Проверить доступность с целевых мобильных операторов: расположение VPS само по себе её не гарантирует.
7. Подтвердить работу соседних служб и документировать результат. GitHub-публикация и права на материалы проверяются отдельно.

## Обновление и rollback

Обновлять между партиями: комнаты живут в памяти, рестарт удаляет их и счёт/бинго. Не запускать несколько процессов за балансировкой без отдельного изменения архитектуры.

Сохраните ссылку current на предыдущий релиз и резервные копии конфигов, если они меняются. Установите новый release отдельно, проверьте комплектность, атомарно переключите current и перезапустите только службу игры. Не удаляйте старый release до успешных health/HTTPS/assets/SSE-проверок.

При ошибке верните current на предыдущий комплектный release и перезапустите только игру, затем повторите health/HTTPS-проверки. Комнаты после rollback не восстанавливаются. Caddy обычно не нуждается в reload при обновлении кода; если его конфиг менялся, восстановите отдельную резервную копию, проверьте и затем reload. Не останавливайте соседние сайты.

Завершение Node по SIGTERM/SIGINT закрывает SSE и таймеры, затем HTTP; активные HTTP-соединения принудительно закрываются после ограниченного срока. TimeoutStopSec в шаблоне оставляет время на это завершение.

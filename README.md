# «Судья, ты чего?!» — хоккейное дерби

Фанатская неофициальная игра перед матчем «Динамо» Москва — ЦСКА, 22 ноября 2026 года, ВТБ Арена. Две участницы и ведущий открывают один сайт на трёх телефонах. Регистрация не нужна, только ник.

Клиент и сервер написаны на TypeScript. Клиент собирается Vite, сервер работает на Node.js и синхронизирует участников через SSE и POST API.

## Как играть

1. Откройте «Правила»: единый справочник из 17 коротких карточек доступен гостям, в лобби и во время матча. Он готовит ко всем 18 вопросам.
2. Ведущий создаёт комнату и отправляет участницам ссылку либо шестисимвольный код. В ссылке только код, приватного токена нет.
3. Каждая участница входит со своего телефона под своим ником. Когда обе готовы, ведущий начинает матч.
4. Ответы независимы, повторный ответ запрещён. Правильный вариант, пояснение и чужие ответы скрыты до завершения голосования. Ведущий может раскрыть вопрос раньше; пропуск даёт 0 очков.
5. За правильный ответ участница получает +1 игровое очко. Это отдельная система от турнирных очков клубов КХЛ (2/1/0).
6. После каждого из первых двух периодов по шесть вопросов — перерыв; после 18-го вопроса — финал. На арене участницы отмечают персональное бинго.
7. Ведущий может начать реванш: очки и бинго обнуляются. Это также безопасный путь к замене участницы после начала матча: подтвердить реванш, убрать участницу в лобби и пригласить новую.

## Вернуться, заменить телефон, закрыть комнату

Участие сохраняется в `localStorage` этого браузера на этом устройстве. Можно закрыть вкладку и открыть сайт снова, пока комната существует. В приватном режиме или при запрещённом хранилище браузер может удалить данные. На чужом/общем устройстве после игры нажмите «Забыть участие».

«Забыть участие» с подтверждением удаляет локальный ключ. Оно не освобождает серверный слот: в лобби ведущий нажимает «Убрать». Токен исключённой участницы сразу теряет доступ; её открытые вкладки получают уведомление и очищают ключ. Во время матча исключение запрещено, скрытой подмены игрока и счёта нет.

«Закрыть комнату» доступно только ведущему, требует подтверждения, завершает все потоки и удаляет комнату. У подключённых участников удаляется локальная сессия. Отключённое устройство очистит старый ключ при следующем обращении к серверу.

При потере сети показан индикатор переподключения. Клиент держит один поток SSE, останавливает его при уходе в фон и восстанавливает с актуальным состоянием при возврате. Таймаут отсутствия данных — 45 секунд; задержка повторного подключения растёт от 1,5 до 15 секунд. POST-действия автоматически не повторяются. Версия состояния защищает кнопки ведущего от повторного применения, индекс вопроса — от запоздавшего ответа.

## Очистка и простые ограничения

Комнаты в памяти одного процесса, без БД. Рестарт сервера удаляет текущие игры.

- Лобби закрывается после 30 минут без игровых действий, даже с открытой вкладкой. Просмотры и heartbeat не продлевают срок.
- Игра без подключений хранится 2 часа с последнего отключения всех клиентов или действия — что позднее. Подключённая активная игра от краткого обрыва не удаляется.
- Финал без подключений хранится 30 минут с последнего действия/отключения.
- Проверка сроков — раз в минуту; при удалении закрываются SSE и таймеры.
- На IP: 240 API-запросов в минуту, до 8 созданий комнат за 10 минут. Ответ `429` содержит `Retry-After`. Health-check не расходует лимит.
- До 3000 комнат, до 3 SSE на токен, 12 на комнату, 1000 на процесс; общий предел HTTP-соединений — 256. Медленные клиенты с переполненным буфером отключаются. Лимитер имеет ограниченную память и очистку.

При размещении за HTTPS-прокси сервер слушает loopback. `TRUST_PROXY=1` включает обработку `X-Forwarded-For` и `X-Forwarded-Proto` только для соединений от loopback-прокси. Ограничения рассчитаны на небольшую дружескую игру.

Клиент передаёт токены в `Authorization: Bearer` для чтения состояния/SSE и в JSON для POST. Ссылка-приглашение содержит только код комнаты. Снимки состояния не содержат токены ни одной роли; статическая раздача ограничена каталогом клиентской сборки.

## Local Development

Нужна Node **24.22.1** (`.node-version` / `.nvmrc`) и npm **11.19.1** (`packageManager` в `package.json`). Клиент, API и SSE запускаются локально без внешних сервисов.

```sh
npm install
npm run dev
```

Откройте **http://127.0.0.1:5173**. Одна команда запускает Vite, локальный API/SSE на 127.0.0.1:3708, серверный watch и две проверки типов. Ctrl+C останавливает дочерние процессы. Занятый порт приводит к понятной ошибке, без незаметного переключения адреса.

CSS применяется через HMR без перезагрузки. Изменения клиентского TS/HTML автоматически обновляют страницу: участие и серверный счёт восстанавливаются. Изменение серверного TS перезапускает API; текущие dev-комнаты могут потеряться. Ошибки типов видны в терминале, ошибки преобразования клиента — также в браузере. Сервер и клиент не требуют отдельного ручного запуска.

### Три роли в обычных вкладках

Откройте три адреса одного dev-сервера:

- `http://127.0.0.1:5173/?devSession=host`
- `http://127.0.0.1:5173/?devSession=player-a`
- `http://127.0.0.1:5173/?devSession=player-b`

В первой вкладке создайте комнату, в двух других введите её код и ники. Имена namespace только разделяют браузерное хранилище — роль и права по-прежнему определяет сервер. Можно пройти весь матч, проверить независимые ответы, очки, перерывы, reconnect и бинго. Reload сохраняет выбранный namespace и участие.

Без devSession используется обычное общее восстановление браузера. В production параметр devSession игнорируется. Ссылка-приглашение не копирует namespace ведущего и не содержит токен.

### iPhone в той же Wi-Fi-сети

По умолчанию `npm run dev` доступен только на компьютере. Для проверки с телефона **явно** включите сетевой режим:

```sh
npm run dev:lan
```

Откройте на iPhone показанный адрес компьютера в сети, например `http://192.168.1.100:5173` (IP только пример). Компьютер и телефон должны находиться в одной Wi-Fi-сети без изоляции клиентов; локальный firewall должен разрешать выбранный клиентский порт. API остаётся на loopback, запросы и SSE телефона проходят через тот же клиентский адрес. На телефоне нельзя использовать localhost компьютера. Этот режим не является публичным деплоем.

При локальном HTTP Clipboard/Share могут быть недоступны: остаётся показ ссылки/кода для копирования. Полная проверка secure-context функций требует доверенного HTTPS. Физический Safari нужно проверить отдельно: фон/блокировка/возврат, разрыв сети и восстановление. Playwright WebKit не заменяет эту проверку.

### Настройки и команды

При необходимости скопируйте `.env.example` в `.env.local`. Dev-launcher читает DEV_PORT, DEV_API_PORT и DEV_HOST (последний используется только в LAN-режиме). Не помещайте секреты в VITE_*: они могут попасть в браузер. По умолчанию все адреса API и SSE относительные.

| Команда                                   | Назначение                                                              |
| ----------------------------------------- | ----------------------------------------------------------------------- |
| `npm run dev`                             | Клиент, API/SSE, watch и проверки типов                                 |
| `npm run dev:lan`                         | Тот же запуск с явно открытым клиентским интерфейсом                    |
| `npm run typecheck`                       | Проверка сервера, клиента, тестов и конфигурации без emit               |
| `npm run lint`                            | Статический анализ TypeScript, включая async-операции                   |
| `npm run format` / `npm run format:check` | Форматирование / проверка исходников                                    |
| `npm test`                                | Локальные Node unit/integration-тесты                                   |
| `npm run build`                           | Проверка типов и комплектная сборка dist/                               |
| `npm start`                               | Запуск собранного приложения, по умолчанию 127.0.0.1:3707               |
| `npm run test:e2e`                        | Локальные Chromium/WebKit/dev-сценарии                                  |
| `npm run test:release`                    | Независимый dist без devDependencies, SSE и завершение по двум сигналам |

Адрес собранного сервера настраивается переменными HOST и PORT, доверие к HTTPS-прокси — TRUST_PROXY (`0` или `1`). Эти параметры передаются серверному процессу отдельно от клиентской сборки.

### Проверки браузером

После установки зависимостей подготовьте браузеры:

```sh
npx playwright install chromium webkit
```

В Linux необходимые системные библиотеки браузеров можно установить командой `npx playwright install --with-deps chromium webkit`.

Затем:

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm run test:e2e
```

E2E автоматически поднимает собранный сервер на 4173 и dev-сервер на 45173 с API на 45174; все процессы локальные и завершаются по окончании. Порты настраиваются E2E_PORT/E2E_DEV_PORT/E2E_API_PORT. Dev-тест временно меняет и восстанавливает клиентские и серверные исходники и создаёт временный TS-модуль для проверки диагностики HMR. Запускайте его без одновременного ручного редактирования этих файлов. Артефакты находятся в игнорируемом test-results/.

В CI используется `npm ci` с lockfile. Инструменты и текущий результат dependency audit описаны в [docs/DEPENDENCIES.md](docs/DEPENDENCIES.md). Полные сетевые контракты — в [docs/API.md](docs/API.md).

## Архитектура

- src/server — Node HTTP, игровой домен, комнаты, закрытые вопросы и SSE.
- src/shared — публичные контракты, runtime-валидация, правила и миссии.
- src/client — DOM-представления, API/sync/session, интерфейс Ice Arena + Liquid Glass.
- tests — Node-проверки и локальные e2e без чтения глобального состояния страницы.
- deploy — переносимые шаблоны и инструкция.

Используется TypeScript strict с отдельными Node/DOM-конфигурациями. Невалидные HTTP/SSE/storage-данные не подменяют проверенное состояние. Вопросный ключ остаётся только в серверной сборке. Память одного процесса — сознательное ограничение: рестарт удаляет комнаты; несколько процессов за балансировкой не поддерживаются.

## Production-сборка

```sh
npm run build
npm start
```

Сборка создаёт dist/server, dist/shared, dist/client и package.json релиза. Из корня проекта `npm start` запускает dist/server/main.js, по умолчанию на `http://127.0.0.1:3707`. Содержимое dist можно перенести отдельно и выполнить npm start в каталоге релиза: для запуска достаточно Node.js.

Настройка systemd, HTTPS/SSE через Caddy, обновление и rollback описаны в [deploy/README.md](deploy/README.md).

## CI и лицензия

GitHub Actions для push и pull request устанавливает зависимости по lockfile, проверяет типы, lint, тесты, сборку, самостоятельный релиз и локальные e2e. Конфигурация находится в [.github/workflows/ci.yml](.github/workflows/ci.yml).

В `package.json` указан статус лицензии **UNLICENSED**. Источники изображений указаны выше; лицензия кода не распространяется автоматически на сторонние марки и изображения.

## API и согласованность партии

Команды изменения комнаты требуют matchId, который меняется при реванше. Answer также требует index, команды ведущего — текущую version. Сервер отклоняет запросы без обязательных полей и команды, не соответствующие актуальному состоянию. Участие и токены при реванше сохраняются, счёт и бинго сбрасываются. POST при таймауте не повторяется автоматически: клиент восстанавливает актуальное состояние.
